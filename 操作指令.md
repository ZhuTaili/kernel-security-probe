一、实验前说明
==============

  ---------- ------------------------- -------------------------------------------------
  **终端**   **用途**                  **主要操作**
  终端 A     用户态展示界面            运行 sudo ./secprobe_monitor，保持界面开启
  终端 B     普通用户测试              执行 nc、curl、普通文件读取与网络测试
  终端 C     root 管理与敏感文件测试   加载/卸载模块、准备演示文件、执行 root 文件测试
  ---------- ------------------------- -------------------------------------------------

判断规则摘要
------------

  -------------- ------------------------------------------- --------------------------------
  **检测类别**   **触发行为**                                **预期展示**
  程序执行       执行 nc / ncat / netcat / nmap / socat 等   EXEC / MEDIUM
  敏感文件       读取演示敏感文件或凭据文件                  FILE / HIGH
  敏感文件       写入受保护文件（用演示文件验证）            FILE / CRITICAL
  网络连接       普通程序连接观察端口 8888                   NET / HIGH
  网络连接       nc 等工具连接观察端口 8888                  EXEC / MEDIUM + NET / CRITICAL
  -------------- ------------------------------------------- --------------------------------

二、打开工程并重新编译
======================

虚拟机重启后，先在普通用户终端中打开原工程，重新编译用户态程序和内核模块。

1. 打开工程目录并查看已有文件
-----------------------------

> cd \~/kernel-security-probe\
> find . -maxdepth 2 -type f \| sort

应能看到以下关键文件：

> ./common/secprobe_event.h\
> ./kernel/Makefile\
> ./kernel/secprobe.c\
> ./userspace/Makefile\
> ./userspace/secprobe_monitor.c

2. 编译用户态展示程序
---------------------

> cd \~/kernel-security-probe/userspace\
> make clean\
> make\
> ls -l secprobe_monitor

正常情况下应生成可执行文件 secprobe_monitor。

3. 编译内核模块
---------------

> cd \~/kernel-security-probe/kernel\
> make clean\
> make\
> ls -l secprobe.ko

正常情况下应生成 secprobe.ko。若出现 BTF 相关提示但最终生成 .ko
文件，可继续测试。

三、加载内核模块并准备测试环境
==============================

以下操作在终端 C 中完成。终端 C 后续保持 root 状态，不要关闭。

1. 进入 root 环境并进入内核模块目录
-----------------------------------

> sudo -i\
> cd /home/pluto/kernel-security-probe/kernel

2. 卸载可能存在的旧模块、清空旧日志并加载当前模块
-------------------------------------------------

> rmmod secprobe 2\>/dev/null \|\| true\
> dmesg -C\
> insmod ./secprobe.ko watch_ports=8888

3. 检查模块是否加载以及 Netlink 通道是否建立
--------------------------------------------

> lsmod \| grep secprobe\
> dmesg -T \| grep SEC_PROBE \| tail -n 20

正常应至少看到以下关键内容：

> secprobe \... \...\
> SEC_PROBE: netlink alert channel created: protocol=31 group=1\
> SEC_PROBE: registered probe: security_bprm_check\
> SEC_PROBE: registered probe: security_file_permission (read/write
> aware)\
> SEC_PROBE: registered probe: security_socket_connect\
> SEC_PROBE: module loaded successfully, active_security_categories=3\
> SEC_PROBE: configured watched port\[0\]=8888\
> SEC_PROBE: userspace monitor: start secprobe_monitor to receive alerts

4. 创建安全演示文件并清除准备过程日志
-------------------------------------

用专门的演示文件验证敏感文件写入规则，避免实际修改
/etc/passwd、/etc/sudoers 或 /etc/shadow。

> printf \'secprobe demo secret\\n\' \> /root/secprobe_demo.txt\
> dmesg -C

四、启动用户态实时展示界面
==========================

新开终端 A，在普通用户提示符下执行：

> cd \~/kernel-security-probe/userspace\
> sudo ./secprobe_monitor

正常情况下，终端 A 会显示实时监控界面：

> ======================================================================\
> Kernel Security Probe Monitor\
> ======================================================================\
> Communication : Netlink realtime alert channel\
> Detection : Completed inside kernel module secprobe.ko\
> Display note : Short duplicate events are merged as xN\
> \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--\
> Received alerts : 0 MEDIUM: 0 HIGH: 0 CRITICAL: 0\
> Type summary : EXEC: 0 FILE: 0 NET: 0\
> \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--\
> Recent kernel-confirmed alerts:\
> \
> Waiting for alerts from kernel module\...\
> \-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\-\--\
> Press Ctrl+C to exit.\
> ======================================================================

  ---------- --------------------------------------------------------------------------------------------------------
  **注意**   监控程序只能接收它启动之后的新告警，不会自动展示此前 dmesg 中的历史日志。执行测试期间保持终端 A 不动。
  ---------- --------------------------------------------------------------------------------------------------------

五、验证正常行为不会产生告警
============================

该步骤用于证明当前规则不会将高频正常行为误判为风险事件。执行前，终端 A
中的 Received alerts 应为 0。

1. 在终端 B 中执行普通读取
--------------------------

> cat /etc/passwd \> /dev/null\
> cat /etc/group \> /dev/null

2. 在终端 C（root）中执行 root 配置文件读取
-------------------------------------------

> cat /root/.bashrc \> /dev/null\
> cat /root/.profile \> /dev/null\
> cat /root/.bash_history \> /dev/null

3. 在终端 B 中测试普通程序连接普通端口
--------------------------------------

> python3 -m http.server 8000 \--bind 127.0.0.1 \>/tmp/http8000.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> curl -s http://127.0.0.1:8000/ \>/dev/null\
> kill \$P

预期结果：终端 A 不增加任何告警记录，统计仍保持为：

> Received alerts : 0\
> Type summary : EXEC: 0 FILE: 0 NET: 0

六、验证可疑命令执行告警
========================

在终端 B 中执行：

> nc -h \>/dev/null 2\>&1

预期终端 A 新增：

> EXEC MEDIUM EXEC \... target=/usr/bin/nc\
> rule=SUSPICIOUS_TOOL

该结果说明：内核态已识别可疑工具启动，并通过 Netlink
将告警实时发送给用户态界面。

七、验证敏感文件读写分级告警
============================

以下操作均在终端 C（root）中完成。

1. 读取安全演示文件
-------------------

> cat /root/secprobe_demo.txt \> /dev/null

预期终端 A 新增：

> FILE HIGH READ \... target=/root/secprobe_demo.txt\
> rule=DEMO_SECRET

  ---------- -----------------------------------------------------------------------------------------------------------------
  **说明**   cat 读取小文件时可能产生两次底层读权限检查，界面可能显示为 x2。这是正常现象，表示展示层已将短时间重复读取合并。
  ---------- -----------------------------------------------------------------------------------------------------------------

2. 写入安全演示文件
-------------------

> printf \'modified by test\\n\' \>\> /root/secprobe_demo.txt

预期终端 A 新增：

> FILE CRITICAL WRITE \... target=/root/secprobe_demo.txt\
> rule=DEMO_SECRET

3. 可选：读取真实凭据文件
-------------------------

> head -n 1 /etc/shadow \> /dev/null

预期终端 A 新增：

> FILE HIGH READ \... target=/etc/shadow\
> rule=CREDENTIAL_SECRET

  ---------- ---------------------------------------------------------------------------------------------------------------------------------------------
  **安全**   只允许读取验证，不要对 /etc/shadow、/etc/passwd、/etc/sudoers 执行写入测试。受保护文件的写入规则已经通过 /root/secprobe_demo.txt 安全验证。
  ---------- ---------------------------------------------------------------------------------------------------------------------------------------------

八、验证网络连接分级告警
========================

模块加载时配置了 watch_ports=8888，因此 8888
是本次实验的重点观察端口，而不是被固定认定为"所有恶意端口"。

1. 普通程序连接观察端口：NET / HIGH
-----------------------------------

在终端 B 中执行：

> python3 -m http.server 8888 \--bind 127.0.0.1 \>/tmp/http8888.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> curl -s http://127.0.0.1:8888/ \>/dev/null\
> kill \$P

预期终端 A 新增：

> NET HIGH CONNECT \... target=127.0.0.1:8888\
> rule=WATCH_PORT_CONNECT

2. 可疑工具连接普通端口：NET / HIGH（可选增强验证）
---------------------------------------------------

> python3 -m http.server 8001 \--bind 127.0.0.1 \>/tmp/http8001.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> printf \'GET / HTTP/1.0\\r\\n\\r\\n\' \| nc 127.0.0.1 8001
> \>/dev/null\
> kill \$P

预期终端 A 新增：

> EXEC MEDIUM EXEC \... target=/usr/bin/nc\
> NET HIGH CONNECT \... target=127.0.0.1:8001\
> rule=SUSPICIOUS_TOOL_CONNECT

3. 可疑工具连接观察端口：NET / CRITICAL
---------------------------------------

在终端 B 中执行：

> python3 -m http.server 8888 \--bind 127.0.0.1 \>/tmp/http8888.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> printf \'GET / HTTP/1.0\\r\\n\\r\\n\' \| nc 127.0.0.1 8888
> \>/dev/null\
> kill \$P

预期终端 A 新增：

> EXEC MEDIUM EXEC \... target=/usr/bin/nc\
> rule=SUSPICIOUS_TOOL\
> \
> NET CRITICAL CONNECT \... target=127.0.0.1:8888\
> rule=TOOL_AND_WATCH_PORT

该结果体现组合判断逻辑：仅执行可疑工具时为中风险；当可疑工具进一步连接管理员配置的观察端口时，告警升级为严重级别。

九、生成用于报告或汇报的干净演示界面
====================================

完整测试后界面记录可能较多。为获得清晰截图，可重新启动用户态监控程序，仅执行核心演示操作。

1. 在终端 A 中退出并重新启动监控界面
------------------------------------

> \# 在正在运行的监控界面按 Ctrl+C\
> \
> cd \~/kernel-security-probe/userspace\
> sudo ./secprobe_monitor

2. 在终端 C 中触发文件读写分级告警
----------------------------------

> cat /root/secprobe_demo.txt \> /dev/null\
> printf \'final demo\\n\' \>\> /root/secprobe_demo.txt

3. 在终端 B 中触发普通连接观察端口告警
--------------------------------------

> python3 -m http.server 8888 \--bind 127.0.0.1 \>/tmp/http8888.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> curl -s http://127.0.0.1:8888/ \>/dev/null\
> kill \$P

4. 在终端 B 中触发组合严重告警
------------------------------

> python3 -m http.server 8888 \--bind 127.0.0.1 \>/tmp/http8888.log
> 2\>&1 &\
> P=\$!\
> sleep 1\
> printf \'GET / HTTP/1.0\\r\\n\\r\\n\' \| nc 127.0.0.1 8888
> \>/dev/null\
> kill \$P

最终界面应集中展示以下关键结果：

> FILE HIGH READ /root/secprobe_demo.txt\
> FILE CRITICAL WRITE /root/secprobe_demo.txt\
> NET HIGH CONNECT 127.0.0.1:8888\
> EXEC MEDIUM EXEC /usr/bin/nc\
> NET CRITICAL CONNECT 127.0.0.1:8888

十、结束测试并卸载模块
======================

终端 A 中按 Ctrl+C 退出用户态展示程序；随后在终端 C（root）中执行：

> rmmod secprobe\
> lsmod \| grep secprobe\
> dmesg -T \| grep SEC_PROBE \| tail -n 20

其中 lsmod \| grep secprobe 无输出，说明模块已经卸载。
